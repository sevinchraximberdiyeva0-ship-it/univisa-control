# Architecture

The repository is an npm-workspaces monorepo. `apps/web` is a responsive React frontend using React Router, TanStack Query, React Hook Form/Zod and Tailwind. `apps/api` contains an Express REST API, Prisma schema/migrations, development seed and a separate BullMQ worker entry point.

PostgreSQL is the source of truth. Redis queues hold IDs only, with no document or phone payload. The scheduler runs every 30 seconds independently of browsers, reconstructs missing schedules and enqueues due outbox records. Queue retries cannot bypass persistent delivery state. External provider acceptance remains separate from delivery confirmation.

Users belong to one university. All authenticated reads derive university identity from the session, never from request body. Students see their own linked registry record. Faculty coordinators see their assigned faculty. Auditors and coordinators are read-only. University administrators control staff/settings; international officers manage documents. Super-admin accounts have explicit university listing/provisioning endpoints; student-record queries stay within the session tenant. Cross-tenant impersonation is not provided. Composite foreign keys prevent cross-tenant student/faculty/document relations. Auxiliary identifiers are checked through scoped services before writes.

Sessions are random opaque tokens stored only as SHA-256 hashes. Cookies are HttpOnly/SameSite with Secure in production. Mutations require an exact allowed Origin and session-bound CSRF token. Staff must enroll TOTP; MFA secrets are AES-256-GCM encrypted and accepted time steps are recorded to prevent reuse. Fixed session expiry is used rather than client refresh tokens. Disabled accounts cannot use existing sessions.

Phone values and document bytes are AES-256-GCM encrypted with randomized nonces. Storage keys are random and never derived from filenames. Downloads are authorized, audited, no-store attachments. MIME magic and upload size are checked. Production still needs antivirus/quarantine, key-management and rotation, storage-volume encryption, and a reviewed retention runner. Do not place the private storage directory under a public web root.

Renewal verification locks the document row, checks base version and workflow state, inserts the new verified version, cancels old pending records, plans reminders, creates confirmation outbox records and logs the action in one database transaction. Delivery acquires the same row lock before checking current version and contacting providers. A send already in flight completes before approval commits. A repeated verified decision is idempotent; obsolete concurrent applications return conflict.

An external send and a PostgreSQL commit cannot be atomic. Before contacting a provider, delivery commits an independent SENDING reservation while holding the document lock. A process crash leaves this reservation in place, preventing automatic replay; stale reservations become UNKNOWN with a staff task. A crash before contacting the provider may therefore require manual recovery even though no message was sent. Explicit temporary rejections alone return to PENDING with bounded backoff. This is conservative reconciliation, not an exactly-once delivery guarantee. Production provider-specific reconciliation and process-level fault-injection tests remain necessary.

Audit events store internal entity references, action and actor, not passport numbers, message text or tokens. Audit storage is append-only through the API, but database owners retain access; production should replicate audit events into tamper-resistant storage. Application logs omit request bodies, credentials, URLs containing bot tokens, and personal details.
