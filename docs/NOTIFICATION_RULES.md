# Notification rules

Defaults: 30, 21, 14, 7, 6, 5, 4, 3, 2, 1, 0 university-local calendar days before expiry. These are configurable reminders, not legal deadlines. Dates are PostgreSQL DATE values; instants are UTC. Luxon performs calendar arithmetic in the configured IANA zone (default Asia/Tashkent). Delivery window is start-inclusive/end-exclusive, initially 09:00–18:00.

Newly added documents inside the warning window receive one catch-up reminder and future milestone reminders. Missed historical milestones are not replayed. No external expiry reminder is sent after expiration; an idempotent staff task opens instead. Overdue documents receive a bounded human-review task, not unlimited automated messaging.

Every reminder has a unique key containing document ID, verified version, kind, local schedule date and channel. PostgreSQL rows are the durable outbox. Redis may be rebuilt; workers reread current database state before each send. A pending renewal leaves existing reminders active. Verification creates a new version, cancels pending old rows, schedules the new dates and queues three confirmation channels in the same transaction. Confirmations are immediate and bypass reminder quiet hours.

Default implementation queues SMS, Telegram and in-app reminders together at each threshold. Configurable Telegram-preferred/SMS-fallback routing, mandatory-communication overrides, and per-student preference editing remain future work. SMS adapters include mock and DevSMS (+998 documented route). Mock records never become DELIVERED from receipts. DevSMS requires two live gates and university provider selection; send acceptance is not delivery.

At 14 days and expiration day, the default rules also create an officer task. Unavailable/unverified phones, unlinked or blocked Telegram accounts, and exhausted quota produce action items. SMS requires staff-recorded verification evidence; no OTP delivery claim is made. Accepted SMS needs a provider-specific authenticated receipt for DELIVERED. Telegram API acceptance remains ACCEPTED because the Bot API does not provide a reliable recipient delivery/read receipt.

Explicit TEMPORARY provider rejection retries at 30, 60, 120 seconds (at most four attempts); a longer provider retry-after is respected up to one hour. Permanent failures are FAILED, blocked Telegram is UNAVAILABLE. BullMQ operational failures have bounded exponential retries and repeated exhaustion creates an action item. Retained failed queue entries are removed/reconstructed from pending database rows. Ambiguous network failures are UNKNOWN and require human/provider reconciliation. Never automatically replay uncertain sends. Telegram update deduplication, account changes and encrypted response outbox are now committed together. Interrupted response sends also become UNKNOWN rather than being replayed blindly.

Missed pending milestones are coalesced to the most recent due milestone, and a unique delivery-day reservation prevents multiple reminder sends for one version/channel/day after downtime. SMS receipts use tenant-specific HMAC-SHA256 of timestamp plus exact raw JSON bytes with a five-minute freshness window. Authenticated status polling checks up to 12 times with capped backoff; no receipt means accepted remains unconfirmed and creates a staff task. Telegram stays ACCEPTED, never DELIVERED based on the Bot API alone.

Overdue offsets are configurable through SMS Management or PUT /api/notifications/overdue-policy (up to 12 offsets, each 1–365 days). Defaults are 1,3,7,14,30. Each due offset creates one staff task per document version. No student overdue messages are automatically sent. Verified renewals resolve document-version escalation tasks.

Configuration changes increment a university schedule revision, lock current documents, cancel pending reminders and replan them transactionally. Records already sent or uncertain for the same document version/channel/date are not regenerated. Date changes occur through verified versioning, which also cancels old pending reminders. No policy should be marked legally approved without authorized university counsel review.
